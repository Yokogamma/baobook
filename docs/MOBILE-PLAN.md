# Мобильная версия «Чистого листа»: план доработок для ревью

Дата: 2026-10-03. Приложение: `sheet/index.html` (один файл, vanilla JS, PWA, без сборки). Живая версия: https://yokogamma.github.io/mockups/sheet/. Тесты: `sheet/tests/` (Playwright, 13 сценариев, запуск описан в `sheet/tests/README.md`). Контекст проекта и состояние хранилища: `sheet/SYNC-PLAN.md`.

Документ описывает, что именно будет меняться в мобильной версии, почему, в каком порядке и как это проверяется. Каждый пункт содержит спецификацию поведения, точки в коде, риски и критерии приёмки, чтобы ревьюер мог проверить PR по чек-листу, а не по ощущениям.

## 1. Исходные факты

Измерено в эмуляции телефона (Chromium, 390×844, `hover: none`, `pointer: coarse`), сценарий `audit-mobile` воспроизводится вручную по шагам ниже.

| Проблема | Факт | Где в коде |
|---|---|---|
| Шапка области на узкой карточке | Название уходит на вторую строку под кнопками, шапка 68 px вместо 32 | CSS `@container (max-width:420px)` и `@media (hover:none){ @container (max-width:640px) … }` для `.ablk .ctitle` |
| Область нельзя тащить за шапку | Касание шапки и движение на 120 px не меняют позицию | `drag(b, grip)` навешивается только на `.grip` |
| Ручка ⋮⋮ на сенсорном экране | 20×24 px, прозрачность 0.28, стоит слева от карточки | `.grip`, `@media (hover:none){ .grip{opacity:.28} }` |
| Конфликт при выделении текста | Системное меню Android у выделения, наша панель над клавиатурой, панель клавиатуры; кнопка «+» перекрывает нашу панель на 52 px и закрывает «Копіювати» | `#bubble`, `placeBubble()`, `.fab`, правило `#undo.show ~ .fab` прячет «+» только для плашки отмены |
| Дублирование копирования | Наше «Копіювати» в панели повторяет «Копировать» системного меню | `#bubble button[data-act="copy"]` |
| Размер текстовых блоков на сенсорном экране | Ручка размера выключена (`display:none` в ленте, `opacity:0; pointer-events:none` на дотике); на планшете в полотне менять размер нельзя | `.sheet.flow .rz`, `@media (hover:none){ .tcard .rz … }` |
| Плашка «Скасувати» | Прижата к низу окна, при открытой клавиатуре может уйти под неё | `.undo{bottom:18px}` |
| Поведение при появлении клавиатуры | В `<meta name="viewport">` нет `interactive-widget`, нижние элементы ведут себя по-разному в версиях Chrome | `<meta name="viewport">` |
| Промахи по шапке | Кнопки 30×28 px без зазора; перемикач вида стоял рядом с «Нова область», промах создавал пустую область | Исправлено в ветке: перемикач перенесён к кнопке меню, на дотике кнопки 40×40 с зазором 4 px |

Что не является багом, но ревьюеру стоит знать: в ленте (экран до 640 px) горизонтальные координаты игнорируются, модель блоков не меняется; удержание ~450 мс создаёт блок; клик по ручке ⋮⋮ без перетаскивания копирует блок; у чипа «код» копирует иконка в правом краю.

## 2. На какие паттерны опираемся

- **Карточка с заголовком-ручкой** (Trello, Milanote, Google Keep, Apple Freeform): заголовок слева в одну строку с многоточием, действия справа, карточку таскают за шапку. На сенсорном экране подъём после удержания 200–300 мс, чтобы не ломать прокрутку.
- **Режим выделения блока** (Freeform, Keynote, Miro на планшете): первое касание выделяет блок, появляется рамка с ручками и мини-панель действий, второе касание входит в текст. Ручки никогда не показываются во время набора.
- **Панель форматирования как аксессуар клавиатуры** (Notion, Craft, Bear): только форматирование, иконки, 44 px цели. Копирование и вставка остаются системному меню. Плавающие кнопки прячутся, пока открыта клавиатура (Material: FAB скрывается в режимах ввода).
- **Переполнение в шапке** (Notion mobile, GitHub mobile): больше трёх действий уходят в «⋯».

## 3. Изменения по пунктам

### 3.1. Конфликт меню при выделении (приоритет 1, ~1 час)

Поведение:

- Кнопка «+» скрыта, пока фокус в любом текстовом блоке, названии кода или области, пока видна панель форматирования и пока открыта панель заметок или режим «как на компьютере». Появляется обратно через 150 мс после потери фокуса, чтобы не мигать при переходе между блоками.
- На сенсорных экранах панель форматирования содержит пять кнопок: B, I, U, S, «</>». «Копіювати» остаётся только на компьютере. Ширина панели не превышает ширину экрана, кнопки 56×40 px.
- Плашка «Скасувати» и панель форматирования позиционируются по `visualViewport` одинаково: низ видимой области плюс `env(safe-area-inset-bottom)`.
- В `<meta name="viewport">` добавляется `interactive-widget=resizes-content`.

Код: `placeBubble()`, `fab`, обработчики `focusin`/`focusout` на `#sheet`, `.undo`, `<meta name="viewport">`, CSS `@media (hover:none)` для `.bubble`.

Риски: `interactive-widget=resizes-content` вызывает перерасчёт раскладки при появлении клавиатуры; у нас раскладка абсолютная, перерасчёт дешёвый, но нужно проверить, что ResizeObserver на листе не переключает режим ленты и не вызывает `applyMode()` на каждое появление клавиатуры (ширина не меняется, только высота, условие `w!==lastW` это закрывает).

Приёмка: в сценарии `apptouch.mjs` при выделении текста `#fab` скрыт, `#bubble` не пересекается с ним; на дотике в панели 5 кнопок; плашка отмены при открытой клавиатуре видна выше низа `visualViewport`.

### 3.2. Шапка карточек на узком экране и перетаскивание за шапку (приоритет 1, ~2 часа)

Поведение области на экране до 640 px:

- Одна строка: название слева с многоточием, минимум 40 % ширины шапки; справа цвет, «⋯», свернуть. Пустое название показывает подсказку «Назва області…». Касание по названию открывает правку, Enter или Esc закрывают.
- Вся шапка, кроме кнопок, является ручкой переноса. Мышью перенос начинается сразу. Пальцем: удержание 250 мс без движения более 8 px поднимает карточку (лёгкая тень и масштаб 1.02), после чего движение переносит; без удержания касание по шапке прокручивает лист. Системное контекстное меню на шапке подавляется (`contextmenu` → `preventDefault`), выделение текста в шапке отключено (`user-select: none`), кроме самого названия в режиме правки.
- Ручка ⋮⋮ остаётся для компьютера и как запасной вариант на дотике; на сенсорных экранах её размер 28×28 px, прозрачность 0.45 у блока в режиме выделения (см. 3.3).

Поведение блока кода на экране до 640 px:

- Одна строка: язык, название с многоточием, «Копіювати» иконкой, замок, «⋯». В «⋯» уходят перенос строк и номера строк. На компьютере шапка не меняется.

Код: `buildArea()` и `buildCode()` (разметка `.cbar`), контейнерные запросы для `.ablk .ctitle` и `.cblk .ctitle`, `drag(b, grip)` получает второй аргумент-источник (шапка) и общий детектор удержания, `holdStart/holdMove/holdEnd` объединяются с логикой переноса (см. 3.4).

Риски: касание по названию против удержания для переноса, решается так: удержание на названии тоже поднимает карточку, правка названия только по короткому касанию; при переносе за шапку в ленте работает та же вставка между соседями, что и для ручки, ничего нового в модели.

Приёмка: в `apptouch.mjs` шапка области на 390 px имеет высоту 32 px, название и кнопки в одной строке; удержание 300 мс на пустом месте шапки и движение на 120 px переносят область, в сохранённой модели меняется только `row`; простое касание шапки не переносит; касание названия открывает правку. В `apparea.mjs` поведение на компьютере не меняется.

### 3.3. Режим выделения блока на сенсорном экране (приоритет 2, ~3 часа)

Поведение (только `hover: none`; на компьютере клик по ручке по-прежнему копирует):

- Касание ручки ⋮⋮ выделяет блок: рамка цветом `--sel-line`, угловая ручка размера 28 px, мини-панель над блоком с действиями «Копіювати», «Видалити», для области ещё «Розгрупувати». Ручка ⋮⋮ выделенного блока видна полностью, перенос начинается движением за неё без удержания.
- Касание по тексту выделенного блока входит в правку, выделение снимается. Касание в любом другом месте, Esc или прокрутка на 40 px снимают выделение.
- Ручка размера: в ленте меняет только минимальную высоту блока (ширина всегда во весь экран), в полотне на планшете ширину и высоту, как на компьютере. Для области то же, для кода ширину и высоту свёрнутого состояния.
- Ручки размера и рамка никогда не показываются во время набора текста. Это закрывает прежнюю жалобу на ручку при печати.

Код: новый класс состояния `.blk.sel`, обработчик на `.grip` для дотика, повторное использование `rz`-логики из `buildText()/buildCode()/buildArea()`, мини-панель как второй экземпляр `#bubble` с другим набором кнопок, `remove()`, `copyBlock()`, `ungroup()`.

Риски: конфликт с «клик по ручке копирует» на устройствах с мышью и сенсором одновременно (Surface, iPad с мышью). Правило: тип указателя события решает, `pointerType === 'touch'` даёт выделение, мышь даёт копирование. Копирование на дотике остаётся через мини-панель, чип и панель форматирования.

Приёмка: в `apptouch.mjs` касание ручки даёт `.blk.sel`, панель с нужными кнопками, видимую ручку размера; перетаскивание ручки размера в ленте меняет `ch` в модели и высоту блока кратно 24 px; касание текста снимает выделение и ставит курсор; «Видалити» в мини-панели удаляет блок с плашкой «Скасувати».

### 3.4. Рефакторинг жестов и шапок (сопровождает 3.2 и 3.3, ~1 час сверх)

- Один модуль жестов `gesture(el, {tapSlop, holdMs, onTap, onHold, onDragStart, onDragMove, onDragEnd, onCancel})` на pointer-событиях с `setPointerCapture`. Его используют создание блока удержанием, перенос за ручку и за шапку, режим выделения. Сейчас это четыре разных обработчика с разными порогами (2 px, 6 px, 8 px) и таймерами.
- Общая функция сборки шапки карточки `cardBar({kind, title, actions, overflow})` для кода и области с одним правилом переполнения в «⋯» и одной раскладкой узкой строки.
- Все правила для сенсорных экранов собираются в один блок `@media (hover:none)` в конце стилей. Сейчас их семь в разных местах, и порядок влияет на специфичность.
- Поведение на компьютере не меняется, это проверяют существующие сценарии `apparea`, `apptext`, `appdrop`, `appundo`, `appfmt`, `appcode*`, `apptitle`, `nl2`, `appstore`.

Приёмка: все 13 сценариев проходят без изменений ожиданий, кроме намеренно обновлённых в `apptouch.mjs` и `appflow.mjs`.

## 4. Порядок PR и объём

| PR | Содержимое | Тесты | Оценка |
|---|---|---|---|
| A | 3.1 целиком плюс мелочи из таблицы фактов (плашка над клавиатурой, viewport) | `apptouch`: 4 новые проверки | ~1 час |
| B | 3.2 шапка области и кода, перенос за шапку, увеличенные ручки; первая часть 3.4 (модуль жестов, шапка карточки) | `apptouch`: 5 проверок; `apparea`, `appcode*`, `apptitle` без изменений | ~3 часа |
| C | 3.3 режим выделения; вторая часть 3.4 (единый блок стилей для дотика) | `apptouch`: 6 проверок; `appflow` 2 проверки на высоту в ленте | ~3 часа |

Каждый PR самостоятельно сливаемый, не ломает компьютер, проходит все сценарии. Публикация после каждого: PR в `main`, GitHub Pages, проверка живой страницы.

## 5. Как ревьюеру проверить руками

1. Открыть https://yokogamma.github.io/mockups/sheet/ на телефоне, создать область кнопкой в шапке, набрать название. Ожидание после PR B: название и кнопки в одной строке, удержание шапки поднимает карточку, движение переносит, простое касание не мешает прокрутке.
2. Выделить слово в текстовом блоке. Ожидание после PR A: кнопка «+» исчезла, панель над клавиатурой без «Копіювати», системное меню Android работает как обычно.
3. Коснуться ручки ⋮⋮ у текстового блока. Ожидание после PR C: рамка, мини-панель, ручка размера; тянуть ручку вниз, высота растёт по сетке; коснуться текста, курсор встал, рамка исчезла.
4. Переключить «как на компьютере» и обратно несколько раз. Ожидание уже сейчас: новые области не появляются; кнопка переключения стоит рядом с меню.
5. На компьютере повторить сценарии из `README.md`: клик создаёт блок, протяжка создаёт область, ручка размера видна при наведении и скрыта при наборе, клик по ручке копирует.

## 6. Вне объёма

- Синхронизация и вход через Google (третий шаг плана, `sheet/SYNC-PLAN.md`).
- Вложенные области, совместное редактирование.
- Изменение ширины текстовых блоков в ленте (ширина там всегда во весь экран).
- Подавление системного меню выделения Android: технически ненадёжно, пользователи ожидают его видеть.

## 7. Открытые вопросы к владельцу

- Нужна ли мини-панель выделения на компьютере тоже (единое поведение) или оставить там клик по ручке как копирование.
- Удержание для подъёма карточки: 250 мс или 350 мс. Короче отзывчивее, длиннее надёжнее отличает прокрутку.
- Оставлять ли ручку ⋮⋮ видимой у всех блоков на сенсорном экране (сейчас 0.28) или показывать только у блока в режиме выделения.
