# «Чистый лист»: хранение и синхронизация. Обзор решений и план

Дата: 2026-09-28. Приложение: `sheet/index.html` (один файл, vanilla JS, PWA, без сборки). Публикация: GitHub Pages собирает ветку `main`, адрес https://yokogamma.github.io/mockups/sheet/. Общение с владельцем на русском, тексты интерфейса, коммиты и README на украинском.

## 1. Что уже сделано (шаг 1, PR #12)

- Заметки лежат в IndexedDB: база `sheet`, хранилище `notes`, ключ `id`. Настройки в localStorage под ключом `sheet:settings` (тема, сетка, правописание, текущая заметка, боковая панель, `lastExport`).
- Запасной вариант: если IndexedDB недоступна или запись не удалась, заметка пишется в localStorage под ключом `sheet:note:<id>`; при старте такие заметки переезжают в IndexedDB (побеждает более новый `updated`), старые ключи удаляются.
- После первого сохранения вызывается `navigator.storage.persist()`.
- Экспорт: файл `chystyi-arkush-ГГГГ-ММ-ДД.json` вида `{app:'sheet', format:1, exported, settings:{theme,grid,spell}, notes:[...]}`; на телефоне через Web Share. Импорт ничего не удаляет: новые заметки добавляются, существующие заменяются только более новой версией.
- Статус «Збережено» в шапке отражает результат реальной записи.

Модель данных (см. `serBlock` и `make` в `index.html`):

- Заметка: `{id, title, blocks:[...], created, updated}` (время в миллисекундах, клиентские часы).
- Блок: `{id, row, text}` плюс `fx` (доля ширины листа) для блоков на листе или `parent` + `col` для блоков внутри области; `kind: 'code' | 'area'` или без kind для текста; размеры `cw`, `ch`; у кода `lang, wrap, num, open, title`; у области `title, color, collapsed`.
- Удаление заметки или блока сейчас необратимо и нигде не помечается (надгробий нет).

## 2. Варианты синхронизации, которые рассматривались

| Вариант | Сервер | Настройка | Офлайн | Реальное время | Приватность |
|---|---|---|---|---|---|
| Приватный репозиторий GitHub через API с токеном | нет | токен на каждом устройстве | да | нет, опрос | данные у GitHub, история версий бесплатно |
| Папка приложения в Dropbox или Google Drive (OAuth PKCE) | нет | вход в аккаунт | да | нет, опрос | данные у облака |
| Supabase или Firebase (аккаунты, база, подписки) | их облако | средняя | Firebase из коробки, Supabase своя очередь | да | у провайдера; бесплатный Supabase засыпает после недели простоя |
| CRDT (Yjs, Automerge) плюс небольшой relay (PartyKit, Cloudflare Durable Objects) | небольшой | высокая | лучший | да | у relay, легко шифровать |
| PouchDB в браузере плюс CouchDB на сервере | свой хостинг | средняя | да | да | свой сервер |

Чистый P2P без сервера в браузере не работает: WebRTC требует сигнальный сервер, а устройства редко бывают онлайн одновременно.

## 3. Практики, которых держимся

- Local-first: копия на устройстве главная, интерфейс не ждёт сеть, синхронизация фоном, статус виден в шапке («збережено локально», «синхронізовано 2 хв тому», «конфлікт»).
- Синхронизация по одной заметке. У заметки и у каждого блока хранится время изменения и идентификатор устройства. Удаления хранятся как надгробия (иначе удалённое воскреснет с другого устройства).
- Слияние на уровне блоков: у блоков есть `id`, побеждает более поздняя версия каждого блока. Если один и тот же блок правили офлайн на двух устройствах, проигравшая версия сохраняется как копия «конфлікт з телефону», а не теряется.
- Оптимистичная блокировка при записи: перед записью подтянуть чужие изменения и слить.
- Когда синхронизировать: через секунду-две после сохранения, при возврате на вкладку, при появлении сети, раз в несколько минут.
- Секретов в статическом сайте нет. Конфигурация Firebase публичная, защита данными правилами доступа. OAuth только по схеме PKCE или через SDK провайдера.
- Шифрование на устройстве для чувствительных заметок (в заметках бывают пароли): ключ из парольной фразы (PBKDF2 или Argon2), AES-GCM из WebCrypto, в облако уходит только шифротекст. Минус: потеря фразы означает потерю данных.
- Тестировать двумя профилями браузера одновременно, с выключенной сетью и со сдвинутыми часами.

## 4. Решение для шага 3: Firebase (Auth через Google + Firestore)

Приложением будут пользоваться разные люди, каждому нужны свои заметки под своим аккаунтом. Firebase выбран потому, что вход через Google встроен, Firestore даёт офлайн-кэш и мгновенные обновления между устройствами, правила доступа изолируют заметки каждого пользователя, а бесплатного тарифа (Spark: 1 ГиБ, 50 тыс. чтений и 20 тыс. записей в день) для заметок хватает надолго. Yjs и собственный relay нужны только для одновременного редактирования одной заметки несколькими людьми; это отложено.

### Что нужно от владельца

1. Проект Firebase в console.firebase.google.com под своим Google-аккаунтом: добавить веб-приложение и прислать конфигурацию (`apiKey`, `authDomain`, `projectId`, `appId`). Она не секретная, хранится в репозитории.
2. Authentication: включить провайдер Google; в Authorized domains добавить `yokogamma.github.io` (и `localhost` для разработки).
3. Firestore: создать базу в production mode; правила доступа будут присланы текстом, их нужно вставить в консоли.

### Открытые вопросы (ответы владельца нужны до начала)

- Шифрование: предложено начать без сквозного шифрования (защита Google-аккаунта плюс правила доступа), затем добавить «закрытые» заметки с парольной фразой. Если шифровать всё сразу, фразу придётся вводить на каждом устройстве, восстановления нет.
- Совместный доступ: начать с личных заметок каждого пользователя; обмен заметками между людьми делать позже.

### Схема данных в Firestore

```
users/{uid}/notes/{noteId}
  title: string
  blocks: { [blockId]: { ...блок как в serBlock, u: updated } }   // карта, а не массив: можно писать по одному блоку
  created, updated: number (мс)
  dev: string            // устройство последней записи
  deleted: number|null   // надгробие заметки
users/{uid}/meta/state   // необязательно: время последней синхронизации по устройствам
```

Удалённый блок остаётся в карте как `{d:true, u:updated}` и вычищается через 30 дней. Идентификаторы заметок и блоков уже случайные, коллизий при слиянии не будет.

### Алгоритм синхронизации

- Локальная очередь изменённых заметок. Отправка: через 1–2 с после сохранения, при `visibilitychange`, при `online`, раз в 5 минут.
- Отправка заметки: взять удалённую версию (из кэша `onSnapshot`), слить по блокам (для каждого `id` побеждает больший `u`, надгробия участвуют наравне), записать результат. Заметка целиком побеждает по `updated` только для `title`.
- Приём: слушатель `onSnapshot` на `users/{uid}/notes`; пришедшее сливается в локальную копию и в IndexedDB; если заметка открыта, перерисовываются только блоки, которые не редактируются в этот момент (фокус и курсор сохраняются).
- Часы: клиентское `Date.now()`, разрыв в ничью решает счётчик устройства; при большом сдвиге часов относительно сервера показывать предупреждение.
- Первый вход: локальные заметки привязываются к аккаунту и отправляются; если в аккаунте уже есть заметки, они сливаются по `id`.
- Выход: локальная копия остаётся, синхронизация останавливается; отдельный пункт «выйти и удалить данные с устройства» для чужих устройств.
- Статус в шапке и в панели: «синхронізовано щойно / 2 хв тому», «офлайн, зміни збережено на пристрої», ошибки.

### Правила доступа (черновик)

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

### Технические заметки

- SDK: модульный Firebase v11 через ESM с `https://www.gstatic.com/firebasejs/`; сервис-воркер кэширует его как шрифты (stale-while-revalidate). Без сети приложение и без SDK работает как сейчас.
- Firestore с `persistentLocalCache` и `persistentMultipleTabManager` (несколько вкладок).
- Вход: `signInWithPopup` на компьютере, `signInWithRedirect` на телефоне и в установленном PWA (в iOS popup ненадёжен).
- Интерфейс: в подвале панели кнопка «Увійти через Google»; после входа email, статус синхронизации, «Вийти».
- Тесты: чистые функции слияния проверяются в Node без браузера; сквозные сценарии с Firebase Emulator Suite (`firebase emulators:start --only auth,firestore`) и Playwright, либо с подменённым адаптером.
- Дальше: шифрование по парольной фразе для отдельных заметок; совместный доступ через коллекцию `shares/{noteId}` со списком uid и расширенными правилами.

## 5. Порядок работ

1. Адаптер удалённого хранилища как отдельный интерфейс (`signIn`, `signOut`, `onAuth`, `push(note)`, `subscribe(cb)`), чтобы Firebase можно было подменить.
2. Модуль слияния по блокам с надгробиями и тесты на чистых функциях.
3. Адаптер Firebase, вход через Google, интерфейс статуса.
4. Сквозные тесты на эмуляторе.
5. README и этот файл обновить.
