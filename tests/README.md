# Baobook tests

End-to-end Playwright scenarios (Chromium). Each file is a standalone scenario. It prints `✓`/`✗` lines and exits with code 1 if anything fails. Every scenario serves `public/` over HTTP with the tiny static server in `lib/server.mjs` (Node only, no dependencies) on `127.0.0.1` with a random port. The app needs a real origin: its language files load with `fetch`, which does not work from `file://`, and the service worker only runs over http(s). Each server is its own origin with its own storage. Every browser context gets `CTX` from the same module: the Ukrainian locale (the checks read Ukrainian UI strings) and clipboard permissions.

```sh
cd /path/to/baobook
npm i --no-save playwright@1.63.0 && npx playwright install chromium   # once; node_modules is gitignored; CI pins the same version
node tests/apparea.mjs
```

The scripts are ES modules, so `playwright` must be in `node_modules` at the repository root (or a symlink or junction to another folder that has it).

The `CHROMIUM` environment variable is the path to a Chromium binary. Without it, the scripts use `/opt/pw-browsers/chromium` if it exists (Claude Code cloud environment), otherwise Playwright's own Chromium.

On Windows, Playwright's Chromium download may time out; use an installed browser instead:

```powershell
$env:CHROMIUM='C:\Program Files\Google\Chrome\Application\chrome.exe'; node tests/appchip.mjs
```

Desktop Chrome on Windows differs from Chromium on Linux in two ways that matter here. It supports the Web Share API with files, so `appsave` stubs `navigator.share`/`canShare` and checks both paths. Its system font, Segoe UI, has taller line boxes, so the bottom panels on touch are a few pixels taller than on Linux. Layout checks compare elements with each other, never with fixed pixel values.

GitHub Actions (`.github/workflows/tests.yml`) runs the same scenarios on every PR and on pushes to `main`; screenshots from the run are in the `tests-screenshots` artifact.

Run scenarios one at a time. `appdrop` 5a/5b (mouse drag with coordinate checks) failed once while two other scenarios ran in parallel and passes reliably on its own. This may be test flakiness under load; an app bug is not proven.

Scenarios write screenshots and temporary files to `<tmpdir>/sheet-tests/`, not into the repository.

To reset state between steps, run `localStorage.clear()` + `indexedDB.deleteDatabase('sheet')` after a pause of at least 400 ms (autosave has a 300 ms delay).

The notes panel is 280px wide, so clicks on the sheet start at x≈400.
